# Zhiyu 控制架构契约

本文记录 `grill-me` 拷打后确认的 Zhiyu 当前架构决策。它不是愿景文案，而是后续产品方案、代码实现、测试和评审必须遵守的控制契约。

核心口径：

```text
Chat 是全局人工控制台。
Work 是可独立运行的长期智能体控制器。
Loop、Memory、Connector、Skill、Tool、Artifact、Feedback 是 Work 的组成部件或运行通道。
```

## 1. Chat 与 Work 的关系

### 决策

- `Chat` 可以观察、询问、修改、启动、暂停、纠错项目中的任何对象。
- `Work` 是独立运行的智能体，可以观测、推理、运行 Loop、产生产物、写自己的记忆、调用授权工具修改平台内部受控对象。
- `Chat` 是全局控制入口，但不是越权入口。

### 约束

- 来自 Chat 的任何控制意图，都必须经过目标对象自己的边界策略。
- Chat 不能绕过 Work、Loop、Memory、Connector 或工具的 `Control Contract`。
- Chat 修改系统状态时必须写入审计事件。

### 必须测试

- Chat 发起的命令命中目标对象 `deniedActions` 时必须被拒绝。
- Chat 发起需要审核的动作时必须进入提案或审批流。
- Chat 修改任意记忆时必须生成可审计、可回滚的记忆变更事件。

## 2. Work 的独立运行边界

### 决策

Work 可以真实作用于平台内部状态，但必须按风险分层执行：

- `A. 可直接写`：低风险、可回滚、内部状态。例如运行事件、草稿产物、临时分析结果、LoopRun 状态、source checked 记录。
- `B. 可直接写但必须带证据和审计`：个人记忆、insight、watchlist rationale、量化模拟盘实验参数、候选自选股池提案。
- `C. 只能生成提案，需 Chat 或用户审核`：Work 自身使命、边界、工具权限、审批策略、长期 Loop 频率、角色定义、跨 Work 控制关系、自选股池正式增删、策略大参数切换。
- `D. 永远 denied 或强审核`：真实资金交易、真实付款、删除不可恢复数据、绕过外发审核、读取超出授权的私密源、关闭审计、清空记忆、放宽自身边界。

### 约束

- Work 不能自己批准会扩大自身权限或改变自身控制目标的变更。
- Work 对核心配置的变更必须进入版本化变更流程。
- `denied` 永远优先于 `allowed`。

### 必须测试

- Work 不能直接放宽自身边界。
- Work 不能关闭审计。
- Work 不能把需要审核的动作降级成普通内部写入。

## 3. 记忆作用域

### 决策

- Chat 可以看所有记忆。
- Work 默认只能读取自己的记忆。
- Work 只有在被显式施加或注入其他记忆作用域时，才能读取那些记忆。
- Work 只能写自己的记忆。
- 其他 Work 的记忆对当前 Work 只能作为只读参照。

### 约束

- 读取权限和写入权限必须分离。
- 给 Work 注入其他记忆域，不等于允许它写入其他记忆域。
- Chat 修改任意记忆时，必须记录原值、新值、目标记忆域、原因、来源和可回滚快照。

### 必须测试

- Work 默认不能读取其他 Work 记忆。
- Work 被注入其他 Work 记忆后只能读不能写。
- Work 不能通过工具调用间接写入其他 Work 的记忆。
- Chat 记忆编辑必须可审计、可回滚。

## 4. 原始观测与微信桌面服务

### 决策

- 当前阶段主要真实输入来自微信桌面服务。
- 微信桌面服务是观测采集器，不是某个 Work 的私有输入。
- 微信桌面服务采集到的消息必须先保存为平台级不可改写原始观测事件。
- Work 只能读取、引用、解释原始观测，不能改写原始事实。
- 后续更多真实数据源也遵循同样口径：先 raw observation，再进入理解层。

### 约束

原始观测进入系统后的分层必须清楚：

```text
raw observation
  -> interpretation
  -> memory / task / proposal / reply draft / outbox intent
```

### 必须测试

- raw 微信消息不能被 Work 改写。
- 同一 raw event 可以被多个 Work 引用，但原始事实只有一份。
- Work 产出的解释必须能追溯到 raw event id。

## 5. Work 的观测策略

### 决策

Work 消费原始观测必须通过明确的 `observationPolicy`，不能随意自由拉取所有数据。

每次运行必须留下 `inputSnapshot`，记录：

- 使用了哪些 raw event。
- 使用的时间窗。
- 数据新鲜度。
- provider warning。
- 缺口和省略原因。

### 约束

- Work 是控制器，不是自由浏览器。
- Work 的观测来源、过滤条件、时间窗和触发条件必须可解释。
- 数据源降级必须显式暴露 `provider/detail/warning`，不能伪装成完整数据。

### 必须测试

- WorkRun 必须记录 input snapshot。
- 缺失或降级的数据源必须进入 observability warning。
- Work 不能在无授权 observation policy 的情况下消费敏感观测源。

## 6. Loop 归属

### 决策

凡是涉及智能体推理、记忆读取、工具调用、外部数据源、内部状态写入或外发动作的 Loop，必须归属某个 Work。

只有极低风险、纯本地、无智能判断、无外部写的小提醒，才可以作为平台级 scheduled job 例外。

### 约束

- Loop 是 Work 内部的持续任务，不是孤立 cron。
- Loop 必须继承或引用所属 Work 的控制目标、边界、工具策略、记忆策略和反馈策略。
- Chat 可以创建和管理 Loop，但必须指定其所属 Work，除非它满足平台级 scheduled job 例外。

### 必须测试

- 具备智能体行为的 Loop 没有 Work 归属时不得运行。
- Loop 运行必须绑定所属 Work 的当前配置版本。
- Loop 外发动作必须经过所属 Work 的边界与审批策略。

## 7. Work 配置版本化

### 决策

Work 的使命、边界、工具权限、Loop、记忆策略等核心配置必须版本化，不能只直接覆盖当前状态。

运行事件必须能绑定当时使用的配置版本：

- `manifest.version`
- `controlContract.version`
- `loopSpec.version`
- `toolPolicy.version`
- `memoryPolicy.version`
- `run.configVersion`

### 约束

- 自我变更必须有 diff、审核来源、时间和回滚路径。
- 长期复盘必须能回答：当时系统为什么认为自己可以这么做。
- 直接覆盖只能用于低风险、非核心、可恢复的临时状态。

### 必须测试

- 核心配置变更必须生成新版本。
- WorkRun 必须绑定配置版本。
- 旧版本配置必须可追溯，至少能用于审计和复盘。

## 8. 量化模拟盘定位

### 决策

量化模块兼具两个目标：

- 作为模拟收益优化系统。
- 作为长期智能体控制系统的受控实验场。

当模拟收益优化与可观测、可审计、边界稳定、失效复盘发生冲突时，后者优先。

```text
可观测 / 可审计 / 边界稳定 / 失效复盘 > 模拟收益优化
```

### 约束

- 收益指标可以存在，但不是压倒性第一原则。
- 数据源不完整时，必须暴露缺口、降低置信度或阻断动作。
- 策略失效时，优先记录假设、扰动、失败原因和复盘反馈，不能自动用事后拟合掩盖失效。
- 模拟盘不得拥有真实资金通道。

### 必须测试

- 数据源降级时不能输出伪完整交易判断。
- 交易动作必须有可追溯输入、策略假设和边界检查结果。
- 策略连续失败时必须进入复盘或阻断路径，而不是静默调参。

## 9. 自选股猎手与操盘交易员

### 决策

自选股猎手和操盘交易员必须硬隔离控制目标：

- 自选股猎手负责自选股池维护。
- 操盘交易员只消费当前正式自选股做模拟盘交易和复盘。

### 约束

- 操盘交易员发现池外机会时，只能生成 `watchlist_change_proposal`，不能直接交易。
- 自选股猎手不能直接下单模拟盘。
- 两者共享的是可审计产物，不是互相写对方状态。
- 这个隔离必须落实到工具权限、API 校验、事件审计和测试，不能只写在 prompt 里。

### 必须测试

- 操盘交易员不能交易池外股票。
- 自选股猎手不能调用下单工具。
- watchlist 正式增删必须通过规定的提案或审核流程。

## 10. 失败与重试

### 决策

Work/Loop 失败时默认显式阻断优先，只有满足幂等和风险条件时才自动重试。

```text
显式阻断优先 > 有条件自动重试
```

### 约束

- 只读观测可以重试。
- 幂等、低风险、错误类型明确的步骤可以重试。
- 外部写动作不能盲重试。
- 部分成功必须记录 checkpoint。
- 数据源降级不能通过重试掩盖。
- 连续失败必须进入 `blocked` 或 `needs_review`，不能永远运行。

### 必须测试

- 外部写失败不能无条件重复发送。
- 部分成功必须暴露已完成动作和未完成动作。
- 连续失败必须进入 blocked/needs_review。
- 页面必须能显示最近运行、下次运行、失败原因和心跳。

## 11. 页面职责

### 决策

Work、Loop、量化、记忆相关页面的第一职责是让用户理解控制状态，其次才是提供操作按钮。

优先级：

```text
状态 / 观测 / 边界 / 心跳 / 失败 / 待审 / 下一步 / 来源 > 按钮和表单
```

### 约束

用户进入页面第一眼应该能理解：

- 这个 Work 控制什么。
- 它最近看了什么，多久没看。
- 它现在处于什么状态。
- 它下一步准备做什么。
- 它有没有越权、降级或失败。
- 哪些动作等待批准。
- 它的记忆和结论来自哪里。

### 必须测试

- 页面不能只显示“已启动”，必须显示最近运行、下次运行、失败原因和心跳。
- 待审核动作必须清晰可见。
- 降级数据源和观测缺口必须出现在状态区域。

## 12. 测试优先级

### 决策

当前测试体系第一优先级是：

```text
边界 / 权限 / 审计 / 失败显式化
```

UI、模型质量和收益曲线都重要，但不能优先于长期控制系统的边界和可复盘性。

### 必须测试

- `denied` 优先于 `allowed`。
- Chat 不能绕过目标对象边界。
- Work 只能写自己的记忆。
- 注入的其他 Work 记忆只读。
- 操盘交易员不能交易池外股票。
- 自选股猎手不能下单。
- 外发动作必须进入 outbox 或 approval。
- Work 配置变更必须版本化。
- 失败不能静默吞掉。
- 数据源降级必须暴露 provider/detail/warning。

## 13. 禁止事项

- 禁止把 Chat 做成无审计的超级后门。
- 禁止让 Work 自己给自己放权。
- 禁止让 Work 写入其他 Work 的记忆。
- 禁止把微信原始消息直接变成某个 Work 的可改写记忆。
- 禁止让智能体 Loop 脱离 Work 裸奔。
- 禁止用 prompt 约定替代工具权限和 API 校验。
- 禁止为了模拟收益掩盖数据缺口、策略失效或边界违规。
- 禁止自动任务只显示“已启动”而不显示心跳、失败和下一步。
